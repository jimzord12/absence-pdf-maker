Now you need create a README.md file in the /tasks dir that will explain the entire Task Implementation Cycle Workflow. There are 7 states for a Task that can be in: not_started, implemented, unit_tested, review_fail, review_pass, completed, commited. The workflow is: 1. Identify Task to work on (we will use the tasks/state.json for tracking Tasks, 2. Display the Task you intend to work on and its state, STOP and await for User confirmation, 3. Based on the state do what needs to be done. You do NOT need to pause between the Task's state, however you MUST and this is VERY IMPORTANT, update the tasks/state.json file when you move from one state to another. Once you complete the current working Task, provide a brief description to the USer of what is done and also what files where created, modified or deleted.
