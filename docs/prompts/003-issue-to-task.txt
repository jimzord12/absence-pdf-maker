# Issue-to-Task Conversion Prompt

You are an expert Software Architect and Project Manager. Your task is to convert a detailed **Issue Report** into a structured **Task** for the development team.

## Input
You will be provided with an **Issue Report** (Markdown format) following the project's `ISSUE-TEMPLATE.md`.

## Output Requirements
You must generate two outputs:
1. A **Task Entry** for `docs/tasks/TASKS.md`.
2. A **State Entry** for `docs/tasks/state.json`.

### 1. Task Entry Format (for `TASKS.md`)
The task entry must follow this exact structure:

```markdown
### [TASK_ID]-[TASK_SLUG]

**Identifier:** `[TASK_ID]-[TASK_SLUG]`

**Description:**
[A concise 1-2 sentence description of the work to be done, derived from the Issue Report's Summary and Suggested Solutions.]

**Constraints:**
- [Constraint 1: e.g., "Must use Zod schema validation"]
- [Constraint 2: e.g., "Must integrate with existing React Hook Form setup"]
- [Constraint 3: e.g., "Maintain Greek and English localization"]
- [Add any technical constraints mentioned in the Issue Report or relevant to the project stack (React, TypeScript, Zustand, Tailwind CSS)]

**Acceptance Criteria:**
- [ ] [Verifiable outcome 1: e.g., "Personal Details fields show validation errors for invalid data"]
- [ ] [Verifiable outcome 2: e.g., "Identity Number (ADT) validates against Greek formats"]
- [ ] [Verifiable outcome 3: e.g., "Tests for Greek ADT validation formats pass"]
- [ ] [Add more criteria based on the "Steps to Reproduce" and "Expected Behavior" sections of the Issue Report]
```

**Naming Conventions:**
- `TASK_ID`: The next sequential 3-digit number (e.g., `063`). Check the last entry in `docs/tasks/TASKS.md` to determine this.
- `TASK_SLUG`: A short, descriptive slug (e.g., `fix-issue-012-personal-details-validation`).

### 2. State Entry Format (for `state.json`)
Generate a JSON snippet that should be added to the `tasks` object in `docs/tasks/state.json`:

```json
"[TASK_ID]-[TASK_SLUG]": {
  "state": "not_started",
  "lastUpdated": "[CURRENT_ISO_DATE]",
  "description": "[Short description from the task entry]"
}
```

## Instructions
1. **Analyze the Issue Report:** Read the Summary, Problem Description, and Technical Details carefully.
2. **Extract Requirements:** Identify the core problem and the suggested solution.
3. **Formulate Constraints:** Look for specific technical requirements (files to edit, libraries to use, patterns to follow).
4. **Define Acceptance Criteria:** Create a checklist that, when completed, ensures the issue is fully resolved and verified.
5. **Maintain Consistency:** Ensure the task aligns with the project's architecture (Vertical Slice, Feature-first) and code style (Zod, Zustand, React Hook Form).
6. **Sequential ID:** Ensure the `TASK_ID` is exactly one greater than the current highest ID in `docs/tasks/TASKS.md`.
